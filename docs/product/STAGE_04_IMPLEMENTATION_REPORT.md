## What already existed (audited, not rebuilt)
- **12 specialist responsibilities** bound by `SPEC_ROLE_MAP` (`packages/agents/src/research/specMapping.ts`): Signal Integrity `signal-integrity-v1`, Instrument Validation `instrument-verification-v1`, Market Context `market-context-v1` (the preserved 13th production agent, optional, non-blocking), Technical Structure `technical-structure-v1`, Price Action `price-action-v1`, News & Sentiment `news-sentiment-v1`, Liquidity `liquidity-v1`, Historical Pattern `historical-pattern-v1`, Calendar & Macro `market-calendar-v1` + `macro-global-v1`, Index Constituents `index-constituent-impact-v1`, Independent Challenger `independent-challenger-v1`, Research Synthesis `synthesize()` (`research-synthesis-v2`, a pure function, not an agent). `options-risk-v1` is the extra specialist.
- **Every agent is a deterministic rule engine** (no model); inputs are a closed set of five; outputs are validated against a hand-written contract (`validateAgentContract`, `validateAgentOutput`: field, size, finding and evidence limits, sanitised text). Missing data is UNAVAILABLE (never a pass); a missing required input is SKIPPED; per-attempt timeouts with abort, bounded retries, one fault catch per agent.
- **Orchestrator** (`orchestrator.ts`, `registry.ts`): dependency levels, bounded parallelism, timeouts, out-of-order completion handled, required-agent bookkeeping; engine off by default, kill-switch checked before any work.
- **Regime engine** `market-regime-v1` (`regime/market.ts`): pure, versioned, as-of aware, 5m/15m/1h, IV rank, event risk, correlated-index agreement, uncertainty and conflict flags, FIXTURE/LIVE/HISTORICAL label, `grantsApproval: false`. Tables `market_regimes` (append-only, idempotent).
- **Research package** `research-package-v1` (`research/package.ts`) in the append-only `research_packages` table (shared platform data, unique (candidate, version), per-candidate advisory lock); decisions and risk assessments pin the exact package id (G-41).
- **AI gateway** (`packages/ai/src/gateway`): fail-closed, typed validation, retries, budgets, usage records with RLS; fixture provider only; nothing calls it in production (G-15).

## Pipeline mapping (specification to repository)
Stage 03 candidate (`opportunity_candidates`, G-19) -> eligibility (`runCandidateResearch`: engine flag, expiry, runtime safety) -> instrument validation agent -> market-context agent -> parallel specialists (ordered by the registry) -> challenger (after all) -> `synthesize()` -> `buildResearchPackage` -> `research_packages` -> decision engine reads the package by the id its risk assessment recorded. Research never approves or executes: `grantsApproval` is the literal false.

## Changed in this pass (local, unpushed; CI pending)
1. **Soft dependency (orchestration).** A real defect: the Independent Challenger is a required agent and depended on EVERY peer, including the optional `market-context-v1`, which has no provider (G-16), so the challenger was skipped and every package was RESEARCH_INCOMPLETE. `AgentContract.softDependsOn` orders an agent after optional agents and passes their result when COMPLETED, but never skips it; `market-context-v1` is now the challenger's soft dependency, every other peer stays hard. The pinned test "a dependency that did not complete SKIPS the challenger" is unchanged and still passes for hard dependencies; `historicalConfig.test.ts` now asserts 11 hard + 1 soft (same coverage, more precise). New: `tests/unit/agents/softDependency.test.ts` (8).
2. **A13 options-risk mapping** (`research/optionsRiskMapping.ts`, `options-risk-mapping-v1`): maps an option candidate onto its underlying, claimed contract, contract facts, price grid and risk context. Contract facts (lot, tick) only from a matching, in-force record (a structural `ContractFacts`, compatible with the canonical contract record); no master means `CONTRACT_MASTER_UNAVAILABLE` and no lot or tick (never defaulted); mismatch, expired, not-in-force, invalid lot, unsupported underlying and incomplete claims are REFUSED with reason codes; stale, missing and future-dated quotes are labelled; Greeks are never computed; ticks use exact decimal arithmetic. `options-risk-v1` is mapped as SUPPLEMENTING Market Context and Liquidity (`EXTRA_SPECIALIST_SUPPLEMENTS`; `roleOfAgent` still answers EXTRA, the twelve roles untouched). Findings group into market, liquidity and contract risk (`mapOptionsFindings`; unknown codes reported, never dropped). The package gets an optional `optionsRisk` section only for option candidates. 28 tests.
3. **Research status model** (`research/status.ts`): the eight specified statuses derived from stored candidate state and package (nothing new persisted; FAILED = the dispatcher withdrew the candidate after exhausting attempts with no package). 5 tests.
4. **Research read API** (`apps/api/src/researchApi.ts`): session-protected, read-only, shared permission `research:read`: `GET /research/candidates/:id/package`, `GET /research/packages/:id`, `GET /research/agents`. Documented in `docs/api/openapi-session.json` (14 routes, parity test, 3 tests). 10 tests in `tests/unit/api/researchApi.test.ts`.
5. **Package as-of.** `asOf` (the orchestrator's clock when the run started) is recorded in the package (additive; older packages lack it and must not be read as having a known as-of). `tests/unit/agents/researchTemporal.test.ts` (8): replay determinism, supersession, no other timestamp, regime as-of rules.
6. **G-43 candidate research idempotency** (migration 0044, `research/runRecords.ts`, `storeResearchPackage`). `researchRunKey` = sha256 of the candidate id, the agent set with versions, each agent's input hash and the deterministic engine configuration (never the clock, the worker, concurrency settings or provider data). `research_packages.run_key` (nullable, 64 hex, unique per candidate when present) records it. Inside the existing per-candidate advisory lock the store returns the stored package for a repeated key and writes nothing, so a crash between saving the package and completing the queue item (lease recovery, retry) finds the package instead of appending a duplicate version. A changed candidate or configuration is a different run and a new version. `runCandidateResearch` returns `deduplicated: true` with the STORED package on a repeat.
7. **G-44 per-agent run records** (migration 0044, table `research_agent_runs`, append-only, shared platform data, restrict-FK to the package, unique per agent per package; status/verdict/confidence coherence, format and size checks). One row per agent run (13 per package) is written in the SAME transaction as the package, so a package never exists without its runs and a failed insert leaves no package and no version gap: identity and version, status, verdict, confidence, attempts, input hash, bounded input and output snapshots (an oversize snapshot becomes a marker that keeps its hash), findings, evidence, synthesis metadata, timing, error code. `reportsFromRecords` rebuilds the package's per-agent reports from the rows alone (equal to `package.reports`). Provider data is not stored, so re-executing an agent against a provider is out of scope.
Migration 0044 is additive (one table, one nullable column); no existing table or constraint changed; the five-kind entry vocabulary is untouched.
