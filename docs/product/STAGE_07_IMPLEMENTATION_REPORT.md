## Genuine gaps found and implemented
| Gap | Change |
|---|---|
| G-47 (new) concurrent fills | `fillOrder` read the order and inserted the fill in separate transactions, so the request path and the order-advance cycle could apply one fill step twice. `insertPaperFill` now takes `expectedFilledQuantity` and applies the fill only if the order is still in that state, under a per-order advisory lock in one transaction; the loser re-reads and reports the order as it stands. |
| G-47 (extended) crash between a committed fill and the position update | **Genuine defect found in review.** After such a crash the order is FILLED and the request ELIGIBLE, but `fillOrder` returned early for a FILLED order, a retried request re-ran all checks and hit the same early return, and `advanceOpenOrders` only scans ACCEPTED / PARTIALLY_FILLED orders, so the position was never written. Fixed in four parts: (1) `healEntryFill` (re-derive the position from all fills, then complete the request once the entry is FILLED) is now run after every fill, when `fillOrder` sees an already-FILLED order, and by the recovery sweep; (2) `requestPaperExecution` recognises a retry of an entry that already FILLED and only repairs the follow-up (it creates no order or fill and does not re-validate, so it cannot invalidate a filled entry); (3) `advanceOpenOrders` first runs `healCommittedFills`, driven by the new read-only `listDecisionsNeedingPositionSync` (fills without a position, a position whose quantity differs from its fills, a FILLED entry with an ELIGIBLE request); the report gains `healed`; (4) position creation is conflict-safe (`createPaperPositionOnce`, relying on the existing unique index on `decision_id`) and only the creator records OPENED / ENTRY_FILLED, so a recovery or a racing worker cannot duplicate the opening. No schema change, no migration. **Update-event race (fixed in revision 3):** the position's entry/exit update and its event were separate statements, so concurrent repairs of one fill each appended an event (8 `PARTIAL_EXIT` events reproduced on PostgreSQL). `applyPositionEntrySync` / `applyPositionExitSync` now update conditionally on the target state and insert the event in the same transaction; the outcome is recorded only by the worker whose UPDATE closed the position. Also found and fixed by the real-database run: `createPaperOrder` is serialised per order key (advisory lock). |
| G-27 / M13-09 WATCH | Migration 0045 `decision_watches` (append-only, forced owner RLS, composite FK, idempotent per user and key); `recordDecisionWatch` / `isDecisionWatched`; `POST /decisions/:id/watch|unwatch`; `GET /decisions/:id` returns `watching`. A watch approves nothing and changes no state. Review follow-up: the routes now require their own narrow permission `decisions:watch` (private, TRADER-only) instead of `decisions:read`, because a bookmark is a write and the model separates reads from writes everywhere else. |
| G-27 / M12-28 comparables | `comparablePatterns` + `GET /decisions/:id/comparables`: a read of the stored research package's historical-pattern report; NOT_AVAILABLE with a reason when no provider ran (G-23). |
| M13-18..29 live architecture | `packages/types/src/platform/liveArchitecture.ts`: Assisted Live (confirmation bound to the exact order, one-time, expiring, revocable, fresh risk recheck), Controlled Auto (owner-authorised policy, exact decimal limits, emergency stop, revocation, ownership), broker-report classification (a submission is never a fill; contradictions are UNCERTAIN), and a broker adapter that refuses. Called by no application code (enforced by a source-scan test). Modes stay DISABLED (G-48). |
| Test gaps | Concurrent approve/reject, concurrent execution requests, concurrent fills, permission revocation, risk failing right before execution, cancelled order, watch isolation, and (review follow-up) a REAL SIGKILL crash between a committed fill and the position update with restart recovery (tests/integration/runtime/executionCrashRecovery.test.ts, in the `crash-recovery` CI job), in-memory recovery tests (fillRecovery.test.ts), the crash-seam unit test (crashHold.test.ts) and the permission tests. |
